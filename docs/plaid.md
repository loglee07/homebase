# BluPeak balances (Plaid, read-only)

Optional. Shows BluPeak checking and savings balances in **My accounts**, next to manual accounts and the SnapTrade brokerages (`docs/brokerage.md`, unchanged). Balances only: no transactions are read, nothing moves money.

Sources: <https://plaid.com/docs/link/>, <https://plaid.com/docs/balance/>, <https://plaid.com/docs/link/oauth/>, and the types in the `plaid` and `react-plaid-link` packages.

## What it asks Plaid for
- **Link** is created with `products: ["transactions"]` (the personal-finance use case) and nothing else. `balance` is never in `products` (Plaid initializes it automatically). No Auth, Identity, Transfer, Signal, payment or investments products. Link is restricted to depository checking and savings accounts. Billing note: Transactions is included free during the Trial plan. Subscription products added to an Item during Trial start billing only if you later upgrade to a paid plan, and paid-plan billing is a separate matter you should check with Plaid. The Trial also caps Production Items at 10, and deleting an Item does not free a slot, so the app's cleanup of a wrong-institution or duplicate Item (`itemRemove`) still uses one.
- **Balances** come from `/accounts/balance/get` (real time, one call per Refresh). The **current** balance is what counts toward net worth. The **available** balance (it subtracts pending items) is shown for reference only. A missing balance is "Unavailable", never zero; non-USD and non-checking/savings accounts are listed but not counted. An overdrawn account (negative current) counts as a debt of that positive amount, subtracted once.
- Only these six Plaid calls exist in the code (a test enforces it): `linkTokenCreate`, `itemPublicTokenExchange`, `itemGet`, `itemRemove` (only to delete an Item this app just created that must not be kept), `institutionsGetById`, `accountsBalanceGet`.

## BluPeak identity and coverage
- Published institution id: `ins_109960`. In **production**, before a Link token is created the server calls `/institutions/get_by_id` and requires that id to resolve to a name containing "BluPeak" and to list `transactions`. After Link, the server exchanges the public token itself and calls `/item/get`; the Item's institution must be `ins_109960`. Otherwise the new Item is removed and nothing is saved. The browser's own metadata is never sent or trusted (only the public token is).
- In **sandbox** there is no BluPeak, so the identity check is skipped (documented in code). Any sandbox bank can be linked.

## Linking, OAuth and the loopback restriction
- "Connect BluPeak" appears only after the local access-code unlock (same session as SnapTrade) and every route runs the same guard: loopback Host, same-origin, session cookie (`/api/brokerage/bank/*`).
- Link opens with `react-plaid-link`. No `redirect_uri` is sent: per Plaid's OAuth docs, desktop web opens the bank's OAuth page in a **popup** without one, so no HTTPS URL, tunnel or deployment is needed. (Plaid requires HTTPS redirect URIs in production, which a loopback app cannot offer; the popup flow avoids that.) Allow pop-ups for the page. Consequence: mobile or in-app browsers are not supported.
- One Item only. A second "Connect" is refused (409), the UI hides it once linked, and a stray second completion removes its new Item. If BluPeak asks you to sign in again, **Reconnect** uses Link **update mode** on the stored Item instead of creating another.

## Where the access token lives
- One file per Plaid environment: `.data/plaid-item.production.enc` and `.data/plaid-item.sandbox.enc` (a fixtures run uses memory only). Gitignored (`/.data/`), outside `public/`, directory mode 700 and file mode 600. AES-256-GCM; the key is `FINANCE_TOWN_DATA_KEY` in `.env.local`, generated by `npm run vault:key` and never printed.
- The environment is part of the encryption (authenticated data) and is stored inside the record. A token file copied or renamed to another environment's name cannot be read, and the server refuses to use or replace a token saved for a different environment (`environment_mismatch`). Cached balances, the refresh cooldown and the include/exclude choices (`plaid:<env>:<id>`) are also kept per environment.
- Atomic and durable: written to a temp file, fsynced, renamed over the old file, directory fsynced. It survives restarts and is read from disk when needed.
- If the file exists but cannot be decrypted (wrong or missing key), it is reported and never overwritten; linking is refused until you restore the key or move the file aside. Back up `FINANCE_TOWN_DATA_KEY` privately.
- The token never goes to the browser, logs, responses or manual backups. Synthetic fixtures use an in-memory vault and never touch this file.

## Behavior shared with SnapTrade
Explicit inclusion per account (nothing counts by default), duplicate warning with "Leave out of net worth" for a manual account named like BluPeak (never deleted), Refresh with a 60 second cooldown (counted from the last attempt), last good snapshot kept and marked **Stale** on failure, "Reconnect BluPeak" when the bank wants a new sign-in, "partial" net worth with a frozen home tier while included balances are not loaded, and a Minimize toggle. Locking removes BluPeak data from the page. Bank data is never in manual exports or `localStorage` (only account ids and on/off choices are, as with SnapTrade).

## Exact local setup
Do this yourself, in your own editor. Never paste credentials into chat.
1. Plaid dashboard: get your **client_id** and the **secret** for each environment you want (<https://dashboard.plaid.com/developers/keys>). Trial plan with real banks = **production** and the production secret. Fake banks for testing = **sandbox** and the sandbox secret. In production, BluPeak access may need to be enabled for your Plaid account; the first real run will tell.
2. `npm run env:init`: appends any missing empty placeholders (`PLAID_CLIENT_ID`, `PLAID_SECRET`, `PLAID_SECRET_PRODUCTION`, `PLAID_SECRET_SANDBOX`, `PLAID_ENV`, `FINANCE_TOWN_DATA_KEY`) to `.env.local` without touching existing values, and prints only names.
3. `npm run vault:key`: generates `FINANCE_TOWN_DATA_KEY` into `.env.local` (not shown) unless one is already set.
4. Edit `.env.local` and fill `PLAID_CLIENT_ID`, the secret(s) and `PLAID_ENV` (exactly `production` or `sandbox`). `PLAID_SECRET_PRODUCTION` / `PLAID_SECRET_SANDBOX` are used for their own environment and win over the shared `PLAID_SECRET`; prefer them so a sandbox run can never use a production secret. `FINANCE_TOWN_ACCESS_CODE` must already be set.
5. Restart: `npm run dev:stop && npm run dev`, open <http://localhost:3000>, choose **My accounts**, open the Bank, unlock, press **Connect BluPeak**, sign in inside the Plaid window, press **Refresh** if balances do not appear, then tick the accounts to include. If you also track BluPeak by hand, use **Leave out of net worth** on that manual account.
## Sandbox test and switching environments
Sandbox shows Plaid's fake banks. Everything from it is labeled "Sandbox: fake banks, not counted", its accounts cannot be ticked, and it never affects your real net worth or home tier. The BluPeak identity check is skipped in sandbox (there is no BluPeak there).
- Switch safely: `npm run plaid:env -- sandbox` (or `production`), then `npm run dev:stop && npm run dev`. The command changes only the `PLAID_ENV` line, refuses if the matching secret or client id is missing, prints names only, and never touches `.data/`. Your production connection stays saved in its own file and comes back when you switch back. Do not delete any token file.
- Sandbox steps: switch to sandbox, restart, unlock, press **Connect**, pick a fake bank and use Plaid's published sandbox test login (see <https://plaid.com/docs/sandbox/test-credentials/>). Balances appear labeled as sandbox.
- If a switch is refused, fix the named missing variable in `.env.local` yourself and retry.

The browser pass caught and fixed a real bug (the session cookie did not reach the BluPeak routes).
- **Sandbox**: a Sandbox Link completed and saved a token (`plaid-item.sandbox.enc`). An earlier Sandbox failure was `INVALID_API_KEYS` from the shared `PLAID_SECRET` not being the Sandbox secret; the fix was setting `PLAID_SECRET_SANDBOX`.
- **Live production, tested 2026-11-01**: Link token creation, popup Link, public-token exchange and the encrypted save all worked for BluPeak (`plaid-item.production.enc`), and **Refresh returned balances**. The first Refresh hit the app's 20 second limit ("Plaid took too long to answer"); the next Refresh took about 7 seconds and worked. Real-time balance asks the bank itself, so it can be slow on the first call. Fix: `accountsBalanceGet` now has a 60 second limit (other calls stay at 20), and failed Link-token, exchange and refresh calls log one sanitized `[plaid]` line (HTTP status, `error_type`, `error_code`, `request_id`; never message text, bodies or tokens).
- Still unverified live: the 60 second limit itself (the successful refresh ran under the old 20 second limit), update mode (Reconnect), the duplicate-link refusal against a real Item, and that balances match your statement (check by eye). Not run live: `itemRemove`, wrong-institution cleanup.
